BUỔI 2: KẾT NỐI DATABASE VÀ QUẢN TRỊ DỮ LIỆU THẬT
Mục tiêu: Thiết lập kết nối CSDL SQL Server và áp dụng kỹ thuật Code First Migration để tạo bảng tự động từ code C#.  
Làm những gì (Nội dung & Thực hành):
Cài đặt 3 gói thư viện NuGet quan trọng phiên bản khớp với .NET vào CẢ 2 project (CMS.Data và CMS.Backend) : Microsoft.EntityFrameworkCore.SqlServer , Microsoft.EntityFrameworkCore.Tools , và Microsoft.EntityFrameworkCore.Design.
Tạo lớp quản trị kết nối trung tâm ApplicationDbContext.cs bên trong project CMS.Data. Khai báo quản lý 8 bảng dữ liệu thật thông qua các thuộc tính kiểu DbSet<T> tương ứng với 8 thực thể đã tạo.  
Cấu hình chuỗi kết nối kết nối cơ sở dữ liệu (Connection String) với tên thuộc tính DefaultConnection trỏ chính xác về địa chỉ máy chủ SQL Server local hoặc SQLEXPRESS vào file cấu hình hệ thống appsettings.json trong project CMS.Backend.
Đăng ký dịch vụ DbContext vào hệ thống dịch vụ ngầm của ứng dụng bằng cách bổ sung lệnh builder.Services.AddDbContext<ApplicationDbContext>(...) bên trong tệp tin khởi chạy Program.cs của CMS.Backend
Đăng ký dịch vụ DbContext vào hệ thống dịch vụ ngầm của ứng dụng bằng cách bổ sung lệnh builder.Services.AddDbContext<ApplicationDbContext>(...) bên trong tệp tin khởi chạy Program.cs của CMS.Backend
Quay lại CategoryController.cs, sửa đổi mã nguồn bằng cách sử dụng cơ chế tiêm kết nối (Constructor Injection) để nạp đối tượng ApplicationDbContext vào controller. Thay thế toàn bộ mảng danh sách dữ liệu giả của Buổi 1 bằng câu lệnh truy xuất gọi trực tiếp dữ liệu từ SQL Server: var data = _context.Categories.ToList();
Phải hoàn thiện những gì (Tiêu chí nghiệm thu & Bài tập):
Mở phần mềm quản trị SQL Server Management Studio (SSMS), xác nhận cơ sở dữ liệu mới (ví dụ: ThaiCMS_DB) được sinh ra tự động thành công và chứa đầy đủ đúng 8 bảng dữ liệu cùng bảng lịch sử hệ thống __EFMigrationsHistory.
Sử dụng tính năng Edit Top 200 Rows trong SSMS để nhập thủ công một vài dòng dữ liệu thật vào bảng Categories. Khi chạy trang web truy cập phân hệ /Category, dữ liệu thật vừa nhập từ database phải hiển thị chuẩn xác lên màn hình.
Hoàn thành bài tập rèn luyện tự làm chủ dữ liệu cho hai phân hệ còn lại : Sửa đổi code, thực hiện tiêm kết nối ApplicationDbContext và dùng lệnh nạp dữ liệu thật tương tự cho PostController.cs và UserController.cs. Thực hiện nạp bảng dữ liệu mẫu thật từ file tài liệu vào SQL Server để chuẩn bị cho các buổi tiếp theo.
BUỔI 3: TRUY VẤN LINQ & THAO TÁC DỮ LIỆU CHUYÊN SÂU
Mục tiêu: Thành thạo cú pháp truy vấn LINQ với EF Core và xây dựng hoàn chỉnh luồng xử lý dữ liệu thêm, xóa, sửa (CRUD).
Làm những gì (Nội dung & Thực hành)
Thực hành nâng cao cú pháp LINQ lọc dữ liệu bài viết theo tham số ID động nhận từ URL chuyên mục (int? id) thông qua màng lọc biểu thức Lambda .Where(p => p.CategoryId == id) và sắp xếp bài viết mới nhất lên đầu bằng .OrderByDescending(p => p.CreatedDate)
Triển khai kỹ thuật liên kết bảng (Eager Loading) bằng việc thêm lệnh nạp chồng .Include(p => p.Category) vào chuỗi truy vấn LINQ để kết nối dữ liệu sang bảng liên quan, lấy được thuộc tính tên danh mục hiển thị ra View, tránh lỗi giá trị rỗng (null).
Cập nhật hàm xem trang chi tiết bài viết Details(int id) trong PostController.cs : dùng hàm .FirstOrDefault(p => p.Id == id) kết hợp .Include() và viết logic kiểm tra bảo vệ hệ thống, nếu bài viết không tồn tại (post == null) lập tức trả về trang thông báo lỗi 404 bằng lệnh return NotFound();
Xây dựng trọn vẹn luồng Thêm mới (Create) dữ liệu cho danh mục tại CategoryController.cs thông qua việc viết 2 Action song hành : Hàm Create() cấu hình giao thức [HttpGet] dùng mở trang hiển thị giao diện biểu mẫu nhập liệu và Hàm Create(Category model) cấu hình [HttpPost] dùng đón nhận gói dữ liệu từ form gửi lên. Thực hiện quy trình ghi dữ liệu bắt buộc gồm 2 bước: Bước 1 thêm vào bộ nhớ tạm hệ thống _context.Categories.Add(model); Bước 2 ra lệnh chốt lưu ghi xuống database thật bằng _context.SaveChanges() rồi điều hướng người dùng quay lại trang danh sách.
Xây dựng luồng Chỉnh sửa (Update) gồm 2 giai đoạn : Giai đoạn GET thực hiện tìm kiếm đối tượng theo Id rồi nạp thông tin cũ đổ lên View form để người dùng chỉnh sửa; Giai đoạn POST tiếp nhận mô hình dữ liệu đã thay đổi, gọi lệnh cập nhật bộ nhớ tạm _context.Categories.Update(model) và chạy _context.SaveChanges() lưu xuống SQL Server.
Phải hoàn thiện những gì (Tiêu chí nghiệm thu & Bài tập):
Thiết kế hoàn thiện cấu trúc tệp biểu mẫu nhập liệu Create.cshtml và tệp chỉnh sửa dữ liệu Edit.cshtml của danh mục. Riêng file Edit.cshtml bắt buộc phải khai báo trường nhập ẩn <input type="hidden" asp-for="Id" /> để giữ định danh bài viết cần sửa, tránh lỗi tạo mới nhầm lẫn.
Cập nhật file danh sách danh mục Index.cshtml, bổ sung thêm các liên kết nút lệnh Sửa và Xóa tích hợp các thuộc tính Tag Helpers (asp-action, asp-route-id) , đồng thời tích hợp đoạn mã Javascript confirm onclick="return confirm('...')", đảm bảo hiển thị hộp thoại hỏi ý kiến xác nhận trước khi xóa để bảo vệ an toàn dữ liệu.
Đối soát kiểm chứng vận hành chạy thông suốt thành công toàn bộ luồng tính năng CRUD danh mục trên trình duyệt và xác nhận sự thay đổi dòng bản ghi tương ứng trong database bằng SSMS.
Hoàn thành các thử thách bài tập tự rèn luyện nâng cao : (1) Hiển thị nhãn tên danh mục tại trang quản lý chi tiết bài viết Post/Details.cshtml sử dụng .Include(); (2) Sửa đổi logic trong HomeController.cs kết hợp chuỗi hàm LINQ nâng cao gồm .OrderByDescending() và .Take(3) để lọc thành công đúng 3 bài viết có ngày đăng gần đây nhất để dàn trang trình bày lên giao diện trang chủ đẹp mắt.
BUỔI 4: ASP.NET CORE MVC CHO TRANG QUẢN TRỊ (ADMIN PANEL) TOÀN DIỆN
Mục tiêu: Thiết lập hệ thống Layout bộ khung chung riêng biệt cho khu vực quản trị và hoàn thiện biểu mẫu nhập liệu nâng cao có tích hợp trình soạn thảo mã HTML và xử lý upload file ảnh vật lý.
Làm những gì (Nội dung & Thực hành)
Tạo file Layout bộ khung quản trị riêng biệt mang tên _LayoutAdmin.cshtml nằm bên trong thư mục hệ thống Views/Shared sử dụng thư viện Bootstrap để phân chia phân tầng giao diện.
Thiết kế cấu trúc thanh thực đơn điều hướng Sidebar cố định bên trái (cột rộng col-md-3), chèn các liên kết sử dụng các thẻ thuộc tính Tag Helpers (asp-controller, asp-action) để di chuyển mượt mà giữa các chức năng bảng quản lý: Bảng điều khiển, Danh mục, Bài viết, và Thành viên. Cấu hình vùng hiển thị nội dung chính linh hoạt ở bên phải (cột rộng col-md-9) thông qua câu lệnh nạp dữ liệu @RenderBody().
Khai báo dòng mã nạp áp dụng Layout mới { Layout = "_LayoutAdmin"; } lên đầu các tệp tin View danh sách (Index.cshtml) quản trị của Post, Category và User để đồng bộ hóa giao diện chung.
Hoàn thiện phân hệ Quản trị Bài viết (Post) liên kết danh mục:
Viết Action Create giao thức GET nạp toàn bộ danh sách phân loại từ bảng Categories chuyển thành cấu trúc SelectList bỏ vào chiếc túi dữ liệu tạm thời ViewBag.CategoryList để làm nguồn dữ liệu cho ô chọn Dropdown ngoài giao diện.
Viết Action Create giao thức POST tiếp nhận đối tượng bài viết chữ kèm đối tượng tệp tin hình ảnh đặc biệt IFormFile uploadImage truyền lên từ máy tính cá nhân. Thực hiện quy trình xử lý File vật lý chuyên nghiệp gồm 4 bước : Xác định vị trí lưu trữ tại thư mục wwwroot/uploads máy chủ (gọi lệnh tự tạo thư mục nếu chưa tồn tại); Sử dụng cơ chế phát chuỗi ký tự ngẫu nhiên duy nhất Guid.NewGuid().ToString() đặt tên file để ngăn chặn tình trạng ghi đè trùng tên ảnh làm mất dữ liệu; Chạy lệnh sao chép chép file luồng dữ liệu vào thư mục lưu trữ máy chủ; Tiến hành lưu trữ địa chỉ URL đường dẫn ảnh dạng chuỗi (ví dụ: /uploads/abc.jpg) vào thuộc tính đối tượng cơ sở dữ liệu thay vì lưu cả tấm ảnh thô làm chậm hệ thống. Sau đó chạy lệnh nạp bộ nhớ và chốt lưu SaveChanges() xuống SQL Server.
Hoàn thiện Action Delete và Action Edit (GET/POST) cho bài viết. Riêng hàm POST cập nhật, sử dụng cơ chế .AsNoTracking() để đọc dữ liệu độc lập từ DB đối soát, xử lý tình huống nghiệp vụ: nếu người quản trị không bấm tải lên file ảnh mới thì phải tìm lại giá trị cũ gán giữ lại, tránh việc CSDL bị ghi đè dữ liệu thành chuỗi rỗng.
Tích hợp trình soạn thảo văn bản giàu tính năng chuyên nghiệp CKEditor 5 thông qua đường dẫn trực tuyến CDN vào phần tập lệnh @section Scripts ở cuối file View nhập liệu bài viết để kích hoạt thay thế cho ô nhập dữ liệu văn bản thô textarea có id là #Content. Ngoài ra, tại các trang hiển thị dữ liệu bài viết ra màn hình (Details.cshtml hoặc Index.cshtml), thực hiện thay thế cách hiển thị thông thường bằng lệnh @Html.Raw(Model.Content) để trình duyệt biên dịch biên dịch chuẩn xác các thẻ định dạng HTML (đậm, nghiêng, chèn bảng) từ trình soạn thảo, không in ra các chữ tag thô rườm rà.
Xây dựng phân hệ Quản trị Thành viên (User) hoàn chỉnh phục vụ bảo mật cho buổi kế tiếp:  
Thiết kế giao diện biểu mẫu thêm mới thành viên Create.cshtml sử dụng thuộc tính định dạng type="password" để ẩn ký tự mật khẩu đảm bảo tính riêng tư khi nhập liệu. Đồng thời thiết lập ô danh sách chọn Dropdown select ràng buộc bắt buộc chọn quyền hạn vai trò tài khoản (Role) chuẩn xác gồm hai chuỗi ký tự phân biệt: "Admin" (Quản trị viên) hoặc "Editor" (Biên tập viên).
Viết Action POST Create trong UserController.cs , sử dụng hàm kiểm tra .Any() đối soát bảng Users dưới database nhằm ngăn chặn không cho phép tạo trùng tên đăng nhập tài khoản đã có sẵn hệ thống. Sau đó chạy lệnh lưu đối tượng vào database.
Hoàn thiện Action Edit (GET/POST) chỉnh sửa tài khoản thành viên. Viết logic xử lý điều kiện tại hàm cập nhật: nếu người quản trị tiến hành sửa đổi thông tin họ tên, vai trò mà để trống hoàn toàn ô nhập mật khẩu mới, hệ thống phải nạp lại chuỗi giá trị mật khẩu cũ từ DB (sử dụng .AsNoTracking()) để giữ lại, ngăn ngừa lỗi mất mật khẩu khiến User không thể đăng nhập lại lần sau.
Hoàn thiện Action Delete xử lý xóa trực tiếp thành viên dựa vào Id nhận được từ nút bấm giao diện.
Phải hoàn thiện những gì (Tiêu chí nghiệm thu & Bài tập):
rục giao diện thanh Sidebar hoạt động ổn định, hiển thị trực quan đầy đủ cấu trúc menu các nút bấm chức năng cùng các biểu tượng đồ họa của Bootstrap Icons chuẩn chuyên nghiệp.
Biểu mẫu thêm bài viết hiển thị khung soạn thảo chữ định dạng của CKEditor 5 thành công. Chức năng thêm mới, chỉnh sửa bài viết vận hành mượt mà, tải thành công file ảnh vật lý lưu vào thư mục hệ thống máy chủ và ghi nhận địa chỉ URL ảnh chính xác vào database bảng Posts.
Giao diện quản lý danh sách thành viên User/Index.cshtml hiển thị đầy đủ thông tin. Khi bấm chọn Sửa thành viên, ô nhập tên đăng nhập Username bắt buộc phải đặt thuộc tính khóa chỉ đọc readonly để cấm người dùng chỉnh sửa danh tính duy nhất, bảo vệ tính toàn vẹn dữ liệu hệ thống.
Hoàn thành đạt yêu cầu chuỗi bài tập thực hành kiểm chứng (Checkpoint) tại phân hệ User : Thử nghiệm sửa họ tên tài khoản nhưng để trống mật khẩu mới, kiểm tra database thấy mật khẩu thô cũ vẫn được giữ an toàn; Thử nghiệm xóa thành viên, dòng bản ghi biến mất hoàn toàn dưới database SQL Server; Thử nghiệm đổi vai trò tài khoản thành viên từ Editor sang Admin, nhãn hiển thị trạng thái phân quyền (Badge màu sắc) ngoài giao diện trang Index phải tự động cập nhật chuyển đổi chuẩn xác từ màu Xanh sang màu Đỏ.
