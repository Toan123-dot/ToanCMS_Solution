BUỔI 6: WEB API & RESTFUL SERVICE TOÀN DIỆN
Mục tiêu: Cài đặt bộ công cụ sinh tài liệu thử nghiệm API Swagger và xây dựng thành công các hàm bất đồng bộ xuất dữ liệu thô định dạng JSON sạch tuân thủ theo chuẩn giao thức kiến trúc RESTful đóng vai trò làm "cửa ngõ" dữ liệu cung cấp cho FrontEnd ReactJS ở các buổi tiếp theo kết nối rút dữ liệu.
Làm những gì (Nội dung & Thực hành):
Mở cửa sổ lệnh Package Manager Console chọn đúng dự án phân hệ CMS.Backend , chạy câu lệnh cài đặt bộ sinh giao diện tài liệu thử nghiệm API của Microsoft: Install-Package Swashbuckle.AspNetCore.  
Tiến hành cấu hình lại file khởi chạy hệ thống Program.cs của CMS.Backend để thiết lập Kiến trúc Lai song hành (Hybrid Rule) chuyên nghiệp, vừa duy trì hiển thị bình thường toàn bộ hệ thống giao diện trang web MVC chạy bằng các file Razor .cshtml cũ, vừa mở thêm cổng dịch vụ Web API mới chạy song song, không dẫm chân hay gây lỗi biên dịch cho nhau
Tại khu vực 1 đăng ký dịch vụ, bổ sung chèn các dòng lệnh đăng ký dịch vụ bóc tách Endpoint và kích hoạt bộ sinh tài liệu API tự động: builder.Services.AddControllersWithViews(); , builder.Services.AddEndpointsApiExplorer(); , và builder.Services.AddSwaggerGen();
Tại khu vực 2 cấu hình các phần mềm trung gian pipeline, chèn các dòng lệnh kích hoạt giao diện tài liệu: app.UseSwagger(); và app.UseSwaggerUI(...) cấu hình hậu tố đường dẫn mặc định truy cập sẽ là /swagger.
Tại khu vực 3 cấu hình định tuyến bản đồ đường đi cuối file, tiến hành phân chia làm 2 phân luồng rõ rệt : Phân luồng A gọi lệnh app.MapControllers(); để tự động nhận diện ánh xạ các địa chỉ Endpoint API mới tuân thủ theo cấu trúc định tuyến; Phân luồng B giữ nguyên lệnh bản đồ mặc định cũ app.MapControllerRoute(name: "default", ...) cho các trang giao diện MVC Razor.
Thực hiện thao tác chính xác trình tự trên Visual Studio để sinh file controller API chuẩn: Chuột phải thư mục Controllers của CMS.Backend chọn Add -> Controller... , nhìn menu bên trái chọn mục API và chọn mẫu API Controller - Empty ở cột giữa (tuyệt đối không chọn nhầm mẫu MVC Controller vì mẫu đó trả về giao diện View HTML rườm rà, không đúng chuẩn thiết kế dữ liệu thô của API). Đặt tên file chính xác số nhiều là: PostsController.cs.
Mở file PostsController.cs vừa tạo, cập nhật các thuộc tính nền tảng: Đặt thuộc tính định tuyến [Route("api/[controller]")] lên đầu lớp để quy định tiền tố đường dẫn lấy dữ liệu thô bắt đầu bằng chữ api/ nhằm phân biệt rõ với đường dẫn hiển thị trang web; Đặt thuộc tính [ApiController] kích hoạt tính năng tự động kiểm tra soát lỗi dữ liệu đầu vào; Thiết lập cho Class kế thừa từ lớp tối ưu bộ nhớ ControllerBase (thay vì kế thừa lớp Controller cũ) giúp tăng tốc độ phản hồi dữ liệu JSON. Viết hàm khởi tạo tiêm kết nối ApplicationDbContext vào controller.
Viết 3 hàm API Endpoint bất đồng bộ (async/await) tuân thủ chuẩn RESTful bên trong Class PostsController:
API lấy toàn bộ bài viết (GET Method): Viết hàm GetAll() gắn thuộc tính cấu hình giao thức [HttpGet]. Vận dụng kỹ thuật gọt tỉa dữ liệu (Projection) bằng lệnh .Select(p => new { ... }) để chỉ chủ động lọc bóc tách lấy các trường dữ liệu cốt lõi ngắn cần thiết đem ra trang chủ gồm Id, Title, ImageUrl, CreatedDate và kéo tên chuyên mục liên kết CategoryName = p.Category.Name thay vì bê nguyên cả trường nội dung văn bản [Content] quá dài, giúp gói tin dữ liệu thô siêu nhẹ, tiết kiệm tối đa băng thông. Chạy hàm trả về gói dữ liệu thô bọc trong lệnh mã trạng thái HTTP 200 thành công: return Ok(posts);
API lấy bài viết lọc theo chuyên mục (GET Method tham số): Định nghĩa đường dẫn chứa biến số động truyền trên URL bằng thuộc tính [HttpGet("category/{categoryId}")], viết hàm GetByCategory(int categoryId) chạy lệnh lọc điều kiện Where(p => p.CategoryId == categoryId) để tự động bắt ID chuyên mục từ Client truyền lên ép vào câu lệnh lọc cơ sở dữ liệu SQL Server
API xem chi tiết 1 bài viết dựa theo ID khóa chính (GET Method theo ID): Định nghĩa đường dẫn nhận tham số ID trực tiếp bằng thuộc tính [HttpGet("{id}")], viết hàm GetDetail(int id) chạy quét tìm dòng bản ghi đầu tiên khớp khóa chính bằng lệnh .FirstOrDefaultAsync(p => p.Id == id). Viết logic bảo vệ kiểm tra: nếu truyền số ID bậy không có thật trong hệ thống (post == null), trả về mã lỗi HTTP 404 đính kèm một gói tin thông báo lỗi nhỏ gọn định dạng JSON return NotFound(new { message = "..." }); để Frontend nhận biết tự xử lý giao diện ; nếu tìm thấy bài viết, trả về nguyên vẹn 100% đối tượng bài viết chứa cả thuộc tính nội dung dài [Content] mang mã HTML định dạng để phục vụ nguồn dữ liệu cho trang đọc báo chi tiết.
Cấu hình chính sách bảo mật CORS (Bật đèn xanh cho ReactJS): Nhằm ngăn chặn lỗi trình duyệt chặn rút dữ liệu đỏ lờm trên Console do ReactJS chạy cổng Port 3000 gọi sang Backend chạy cổng Port khác (lỗi chính sách Same-Origin Policy) , thực hiện chèn bổ sung 2 giai đoạn cấu hình mở cửa CORS vào file Program.cs của CMS.Backend : Giai đoạn 1 đăng ký chính sách, chèn dịch vụ builder.Services.AddCors(...) cấu hình tạo một chính sách tên là "AllowAll" gọi chuỗi hàm mở toang cửa cho phép bất kỳ nguồn origin nào (AllowAnyOrigin()), phương thức nào (AllowAnyMethod()), và thông tin đi kèm nào (AllowAnyHeader()) để phục vụ môi trường thực hành học tập tại lớp không bị nghẽn; Giai đoạn 2 kích hoạt chính sách, chèn dòng lệnh middleware app.UseCors("AllowAll"); đặt nằm đúng vị trí quy định nghiêm ngặt: nằm ngay sau dòng app.UseRouting(); và đứng ngay trước dòng xác thực app.UseAuthentication();.
Đồ án bấm biên dịch Solution thành công hoàn toàn không sinh bất kỳ lỗi đỏ nào (Build succeeded). Khi mở truy cập URL gốc, giao diện website bán hàng truyền thống cũ chạy bằng Razor .cshtml của các buổi trước vẫn nạp chạy mượt mà, đầy đủ cấu trúc CSS định dạng, chứng minh cấu hình kiến trúc lai hoạt động ổn định.
Kiểm thử trực tiếp đối soát cấu trúc chuỗi văn bản dữ liệu đầu ra JSON sạch trả về từ SQL Server thành công qua cả 2 công cụ lập trình chuyên nghiệp:
Giao diện tự động Swagger UI: Truy cập thêm hậu tố đường dẫn /swagger trên trình duyệt. Khung làm việc màu xanh mượt xuất hiện, nhấp chọn mục hàm GET /api/Posts , nhấp chọn nút lệnh Try it out và nhấn nút Execute màu xanh đậm. Hệ thống bắt buộc phải phản hồi mã code trạng thái thành công Code 200 và khung Response body xuất dữ liệu chuỗi văn bản JSON thật bao bọc trong mảng dấu ngoặc vuông [...]
Phần mềm Postman (Quy trình doanh nghiệp): Mở phần mềm Postman trên máy trạm. Chọn giao thức là mẫu GET , dán chính xác địa chỉ Request URL copy sang (ví dụ: https://localhost:7123/api/posts) và nhấn nút Send. Khung kết quả hiển thị Body phía dưới chuyển sang chế độ hiển thị Pretty và định dạng chọn mục JSON phải hiển thị rõ ràng chuỗi dữ liệu phân tầng với tất cả các thuộc tính key tự động chuyển đổi thành ký tự chữ thường đầu (ví dụ: "id", "title", "imageUrl", "categoryName") để chuẩn bị cho ReactJS gọi mảng ở Buổi 8
